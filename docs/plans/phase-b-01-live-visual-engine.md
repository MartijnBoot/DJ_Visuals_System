## Approach

Three new seams, each built where the spec puts it, then wired on the screen page. `audio/`
(new) turns a `MediaStream` into a stream of `AudioFeatures`: pure analysis maths first (T1),
then the `AudioWorklet` processor and the main-thread source helper that maps the worklet's
clock to `performance.now()` and decays the features when blocks stop arriving (T2). `engine/`
grows a shader pass that draws a video texture or a procedural noise field through the two
dials and the features (T3), then the render-scale controller and the latency record (T4),
both as pure functions of timestamps like `stats.ts` today. `web/` gets a capture session
module with no UI (T6: device lists, constraints, persistence, loss and retry), then the Start
flow and the `s` panel (T7), then the overlay lines, `f` and the wake lock (T8). The browser
check gets the fake-media flags and generated fixtures early (T5), so every web task proves
itself in Chromium as it lands; T9 adds the browser proofs that need the whole chain (the look,
the loss paths, the latency number, render scaling), and T10 writes the docs as built.

The worklet is shipped as a second export of `audio/` (`@djv/audio/processor`) that `web/`
imports with Vite's `?worker&url` suffix and hands to `audioWorklet.addModule`. Probed on this
machine (Vite 8.3.8, Node 24.15.0, Playwright's Chromium with the fake-device flags): Vite emits
the processor as one self-contained chunk with no bare import, so the engine-boundary test
applies to it unchanged; `getUserMedia` honours the three `false` constraints; the fake UI flag
auto-grants `getDisplayMedia` with an audio track; a WAV given to
`--use-file-for-fake-audio-capture` reaches the worklet (clicks read RMS 0.86 against silence
0); a Y4M file drives the fake camera; an `AudioContext` created in a click handler starts
`running`; and `AudioWorkletGlobalScope` has `currentTime` and `sampleRate` but no
`performance`, which is why T2 maps clocks through `getOutputTimestamp()`.

Rejected:

- **FFT in the worklet.** Three IIR band-pass filters give the three band energies the spec asks
  for at any window length; an FFT over a 10 ms window cannot resolve 150 Hz, and SD4 wants no
  spectrum.
- **A `SharedArrayBuffer` ring between worklet and main thread.** It needs COOP/COEP headers,
  which is a server change (SD14 forbids one). `postMessage` per window is used; its jitter is
  a named risk.
- **One task for all of `web/`.** Capture, panel and overlay are each near the size limit on
  their own.
- **A test-only hook on `window` to drive loss and GPU load.** Browser tests stub
  `navigator.mediaDevices` and `requestAnimationFrame` through `addInitScript` instead, so no
  test code ships in the page.
- **Committing a WAV and a Y4M fixture.** Both are generated by a few lines of code into the
  temporary directory `playwright.config.ts` already creates; no binary enters git.

**Changed at build (owner, 2026-11-11).** Four decisions above contradicted what the machine
showed; the builder stopped and the owner decided, and the code and the T9 tests follow these:

- **PD2.** `getOutputTimestamp()` maps a context time to when it is *heard*; the graph
  processed it `baseLatency + outputLatency` earlier (63 ms in headless Chromium), so the
  formula as written put `capturedAt` in the future and the overlay read negative latency.
  `capturedAt` now subtracts both, then `baseLatency` once more as SD15 says.
- **PD6.** Headroom is "not above budget" (the one-second mean ≤ 1.1 × the refresh period),
  not "under 0.8 ×": a loop locked to the display never reads under the period, so the old rule
  never stepped up. A step up undone within 10 s doubles the next wait (20, 40, 80 s); one that
  holds 10 s resets it.
- **PD7 / T9 (AC6).** The 120 ms decay stays; the browser test asserts ≤ 0.1 over the *last*
  200 ms of each gap, not the middle, where the pulse's tail still reads about 0.25.
- **PD13 (AC10).** The browser test reads the overlay after 20 s, once start-up has left the
  10 s window; the 50 ms threshold stays (measured p95 20.7 ms on SwiftShader at 640×360).

## Tasks

Each task is one vertical slice that leaves the system working, reviewable in one sitting:
about ≤400 changed source lines (tests do not count) across ≤10 files.

### T1 — `audio/`: the package, the feature shape and the analysis maths
- **Implements:** AC6 (the maths half), AC18, SD4, SD11
- **Expected output:** `audio/` is the fifth workspace package (`@djv/audio`, `exports` `.` and
  `./processor`, no dependency field, `tsconfig` with `lib` `ES2024` + `DOM` and `types: []`).
  `audio/src/features.ts` exports `AudioFeatures` `{ level, low, mid, high, beat, capturedAt }`
  and `ZERO_FEATURES`. `audio/src/constants.ts` names every number: window length in quanta,
  band edges, filter Q, per-feature attack and release smoothing, flux history length,
  threshold factor, refractory and decay times (PD1, PD7). `audio/src/analysis.ts` exports a
  pure `createAnalyser(sampleRate)` with `push(block: Float32Array): FeatureFrame | null` that
  returns one frame per completed window: level (RMS), the three band RMS values through the
  IIR filters, flux and the beat pulse, each clamped to 0..1 and smoothed with the named
  constants, with every release time constant ≤ 300 ms so that silence empties the features
  well inside AC12's second; and a `windowFrames(sampleRate)` helper. `audio/src/index.ts`
  re-exports them.
  `tests/meta/engine-boundary.test.ts` runs its four checks for each of `engine` and `audio`
  (the `./processor` export is a relative path and passes). `eslint.config.js:17` adds
  `audio/**` to the browser-globals block and gives `audio/src/processor.ts`
  `globals.audioWorklet` (used in T2). Tests `audio/src/analysis.test.ts` on synthetic signals
  at 48 kHz and 44.1 kHz: silence gives all zeros; a 60 Hz sine gives `low` high and `mid`,
  `high` near zero, a 1 kHz sine the reverse for `mid`, 6 kHz for `high`; a full-scale square
  wave clamps every feature at ≤ 1; a 120 BPM click train (30 ms bursts of 60 Hz) fires `beat`
  within one window of each onset and never between onsets; white noise at −20 dBFS fires no
  beat after the first second; 1 s of silence after a full-scale signal leaves every feature
  below 0.01; every window is ≤ 10 ms at both rates. About 230 source lines, 10 non-test files
  (at the limit; `pnpm-lock.yaml` is pnpm's output), plus the test.
- **Verification:** `pnpm install && pnpm run test --project unit audio tests/meta/engine-boundary.test.ts && pnpm typecheck && pnpm lint`
- **Depends on:** —
- **Autonomy note:** Builder settles filter design (biquad coefficients are a known formula),
  the mid/high split and the smoothing values, keeping each as a named constant. The shape in
  `features.ts` is the spec's contract and is not to be changed. Stop if any analysis needs a
  package, an FFT library, or a window over 10 ms at 44.1 kHz.

### T2 — `audio/`: the worklet processor and the feature source
- **Implements:** AC2 (the audio half), AC6, AC12 (the decay), SD4, SD15, SD11
- **Expected output:** `audio/src/processor.ts` registers `djv-features`: it feeds each render
  quantum of input channel 0 (channels averaged when more than one) to `createAnalyser`, and
  posts `{ frame, contextTime }` per window, `contextTime` the window's end in context seconds;
  it returns `true` always and tolerates an empty input. `audio/src/worklet-globals.d.ts` per
  PD18. `audio/src/clock.ts` exports a pure `createClockMap()` with `update(contextTime,
  performanceTime)` and `toPerformance(contextTime)`, and `decayFeatures(features, msSinceLast)`
  that holds for the first 100 ms of silence and then fades every feature linearly to zero by
  600 ms (named constants). `audio/src/source.ts` exports
  `createFeatureSource(context, stream, moduleUrl)` returning a promise of
  `{ read(now): AudioFeatures, stop(), lastBlockAt() }`: it calls `addModule` once per context,
  creates the node with no outputs, connects a `MediaStreamAudioSourceNode`, refreshes the
  clock map from `getOutputTimestamp()` every second, and `read(now)` returns the newest frame
  with `capturedAt = toPerformance(contextTime) − baseLatency × 1000`, decayed by
  `decayFeatures` when `now − lastBlockAt` says so. `stop()` disconnects and closes the port;
  the stream's tracks are not stopped here (the session owns them, T6). Tests
  `audio/src/clock.test.ts` (mapping is affine and updates; decay holds 100 ms, is zero at
  600 ms, monotone between) and `audio/src/source.test.ts` with a hand-rolled fake context and
  node (frames flow from port messages to `read`; `read` after 700 ms of no messages is
  `ZERO_FEATURES` except `capturedAt`; `stop` disconnects). About 170 source lines, 5 files.
- **Verification:** `pnpm run test --project unit audio && pnpm typecheck && pnpm lint`
- **Depends on:** T1
- **Autonomy note:** Builder settles message shape, the fake's structure and how the processor
  file is kept free of DOM-only names. Stop if `addModule` needs anything beyond a URL string
  (PD3), or if `getOutputTimestamp` turns out unavailable in the target Chromium.

### T3 — `engine/`: the look — video or noise through the dials and the features
- **Implements:** AC7, AC8, AC9, AC13 (the generative input), SD5, SD10, SD16
- **Expected output:** `engine/src/features.ts` exports the engine's `AudioFeatures` (same six
  fields, no import), `Dials` `{ recognisability, reactivity }`, `ZERO_FEATURES` and
  `DEFAULT_DIALS` `{ 0.3, 0.7 }`. `engine/src/gl.ts` holds small helpers: compile and link a
  program, create a texture, create a framebuffer with a texture, a fullscreen triangle.
  `engine/src/look.ts` holds the vertex and fragment shader sources and a pure
  `lookUniforms(features, dials, timestamp, hasSource)` that maps to the uniform values: zoom
  from `low`, displacement and flash from `beat`, grain and edge gain from `high`, brightness
  from `level`, each multiplied by `reactivity`; block size, posterise levels and feedback
  amount from `recognisability` (PD8); drift tint from `driftColour`, weighted 0 whenever
  `hasSource` is true (PD22). The fragment shader samples the source texture (or value noise
  when `uHasSource` is 0) at block-quantised coordinates, mixes the previous frame sampled at
  block centres, posterises, applies the audio terms evaluated per block (PD22). `engine/src/index.ts` renders each frame into the current ping-pong framebuffer at
  canvas size and blits to the canvas; `Engine` gains `setFeatures`, `setDials`, `setSource`
  (an `HTMLVideoElement` or `null`; uploaded with `texImage2D` each frame while
  `readyState ≥ 2`, otherwise treated as no source); defaults are zero features, default dials,
  no source, so Phase 0 behaviour is the idle look (PD5). Tests `engine/src/look.test.ts`:
  with `reactivity` 0 the uniforms are identical for zero and full features (AC7); with
  `reactivity` 1 the flash and displacement uniforms follow `beat` (AC7); with both dials 0 the
  block size is 1, posterise 256, feedback 0 and tint weight 0 when `hasSource` is true (AC8,
  PD22); with `recognisability` 1 block size is width / 32; every uniform is finite for every
  corner of the input cube. The existing
  `tests/browser/screen.spec.ts` stays green (idle still drifts). About 330 source lines, 5
  files.
- **Verification:** `pnpm run test --project unit engine && pnpm typecheck && pnpm lint && pnpm build && pnpm test:browser`
- **Depends on:** —
- **Autonomy note:** Builder settles GLSL details, the noise function and the strength

## Risks and unknowns

| Risk | Mitigation |
|---|---|
| Worklet-to-main-thread `postMessage` jitter. The probe saw arrival offsets spread over about 38 ms in 3 s, which lands directly in the in-app latency sample. | PD1's 8 ms windows and PD2's clock mapping measure the true age of the data, so the number is honest. If p95 misses 50 ms on the owner's machine because of messaging, the remedy is a `SharedArrayBuffer`, which needs COOP/COEP headers from the server: a server change and an owner stop, not a quiet fix. |
| SwiftShader on CI may not hold the AC10 number at 640×360, or may be slow enough that the render scale steps down during the AC8 pixel tests. | PD13 writes the fallback down; T9's autonomy note pins the cap for the pixel tests if needed. |

| The refresh-rate estimate (PD6) is taken from the first 60 frames, when the page may still be loading. | Snapping to standard rates absorbs noise; the controller only ever compares a one-second mean against 1.1 × budget. If it proves unstable, T4's autonomy note says to stop. |
